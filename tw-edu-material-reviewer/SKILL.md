# 教材與評量品質審查

審查要指出「哪一句、為什麼、怎麼改」，而不是給一段泛泛的評語。腳本只負責核對每個問題確實出現在原文中並編排報告，知識正確性由審查者判斷。

## 定位與邊界

- **做**：三種模式（material 教材、assessment 評量、slides 簡報）的缺陷檢查、原文定位、嚴重度、修正建議、未檢查項目、修正後複查。
- **不做**：重新生成整份教材（交給對應的生成技能）、官方教科書審定、版面視覺的自動判定。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`。

必要情境：教材全文（或可擷取的檔案）、學段與科目、使用目的、答案或規準（若是評量）、可查的來源。沒有原始版面時，只檢查文字，並在未檢查項目中說明。

## 思維路線

1. **選模式**：教材、評量或簡報；只跑該模式需要的檢查。
2. **共通檢查**：
   - 知識與來源：事實、數據、引文是否正確且有來源。
   - 目標對應：內容是否服務學習目標。
   - 材料足夠：學生是否能從提供的材料完成任務。
   - 負荷與可及性：閱讀量、字詞難度、指令清楚度、對比與替代文字。
3. **評量專屬**：答案正確與唯一、誘答合理、題目間線索外洩、配分、題意歧義、規準能否區分表現。
4. **簡報專屬**：每頁教學功能、文字密度、圖表數值與來源、講者備註對頁。
5. **每個問題**：素材編號、原文摘錄（必須能在原文找到）、理由、嚴重度（影響使用／需調整／建議／待查）、修正方式、來源定位。不憑風格喜好列為重大問題。
6. **待查**：需要外部來源才能判斷的，標為待查並保持嚴重度待查，不猜測。
7. **複查**：修正後再檢查一次，確認沒有引入新的矛盾。

## 台灣情境要點

- 自製教材的審查不等於國家教育研究院的教科書審定。
- 引用教科書或他人作品時檢查出處與使用範圍。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。

```bash
python3 "$SKILL_DIR/scripts/generate_review.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_review.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/review.docx"
```

語意閘門會擋下：素材或問題編號重複、引文不在原文中、待查問題卻標了確定的嚴重度。

## 品質關卡

- 每個問題都能在原文中找到位置。
- 嚴重度與影響相符。
- 列出沒有檢查的部分。
- 修正建議是局部修改，不是重寫全部。

## 交接
