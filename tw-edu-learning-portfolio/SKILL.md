# 學習歷程指導

學習歷程的價值在於學生真實的學習軌跡。教師的角色是指導學生找出證據、說清楚歷程與反思，不是替學生寫成漂亮的文章。

## 定位與邊界

- **做**：教師指導版（目標、提問、評價）、學生作品的證據整理、修改歷程、反思提問、成果說明的結構建議、上傳與認證流程提醒。
- **不做**：代寫學生的心得、經歷或反思；虛構活動、時數或成績；升學申請策略。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`（學段、任教科目、是否為導師）。

必要情境：作品或活動紀錄、時間、學生已寫的內容（若有）。學生用代碼。沒有提供的內容一律標待補，不補造。

## 思維路線

1. **分清三種內容**：學生原始成果、學生的反思與說明、教師的建議與評價。輸出中分欄呈現，不混在一起。
2. **找證據**：作品本身、過程紀錄（草稿、照片、數據）、修改前後版本、他人回饋。
3. **歷程結構**：動機 → 過程 → 遇到的困難 → 怎麼修正 → 學到什麼 → 下一步。每一段都要有對應的證據。
4. **反思提問**：用問題引導學生自己寫，例如「哪一次修改讓你的作品最不一樣？為什麼？」，不提供可直接複製的範文句子。
5. **教師評價**：依學習目標與規準，寫出作品展現的能力與可以再發展的方向。
6. **自評與教師觀察不同時**：攤開材料一起討論，不直接改寫學生的自評。
7. **流程提醒**：課程學習成果需任課教師認證，多元表現依學校規定登錄；上傳件數、期程與格式依當年度規定與學校公告。

## 台灣情境要點

- 高級中等學校學生學習歷程檔案包含修課紀錄、課程學習成果、多元表現等；實際項目、件數與期程使用前查詢教育部與學校最新公告。
- 國中小可用作學習檔案與成果發表的整理，不涉及升學上傳。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。每筆紀錄包含 `date`、`artifact`、`evidence`、`reflection`、`next_step`。

```bash
python3 "$SKILL_DIR/scripts/generate_portfolio.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_portfolio.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/portfolio.docx"
```

## 品質關卡

- 反思欄是學生的文字或待補，不是教師代寫。
- 每段歷程都有證據。
- 修改歷程保留前後版本的對照。
- 沒有虛構的活動、時數或成績。

## 交接

- 作品回饋 → `tw-edu-feedback-writer`。
- 專題設計 → `tw-edu-pbl-designer`。
- 學生自行使用的工具：學生端技能套組（tw-stu-learning-portfolio，非本套件）。
