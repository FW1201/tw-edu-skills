# 公開授課與觀議課

公開授課的重點是**看學生怎麼學**，而不是評分授課教師。本技能幫授課教師與觀課夥伴把三個階段串起來：備課時決定看什麼，觀課時只記看到與聽到的，議課時從證據討論下一輪怎麼教。

## 定位與邊界

- **做**：共同備課規劃、觀察焦點與分工、低推論觀察紀錄、議課提問與紀錄、下一輪試作、紀錄的隱私處理。
- **不做**：教師評鑑或考核、評分授課教師、完整教案（→ `tw-edu-lesson-plan-108`）。
- **近似反例**：學校行政要的公開授課彙整表或公告 → `tw-edu-school-document` 或 `tw-edu-official-document`。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`。

先確認階段：只做共同備課、只整理觀課紀錄、只做議課，或三階段完整。學生在紀錄中一律用座號或組別代碼。

## 思維路線

1. **共同備課：先定學習目標**。這節課學生要學會什麼？授課教師最想知道學生哪裡會卡住？
2. **選 1–3 個觀察焦點**：焦點要指向學生的學習，例如「學生如何用圖示說明做法」，而不是「教師提問技巧好不好」。焦點太多就會什麼都看不清楚。
3. **決定要蒐集的證據**：學生作品、對話原話、白板照片（不含正臉）、完成時間。
4. **分工**：每位觀課者負責哪幾組、站在哪裡，盡量看同一群學生的完整歷程。
5. **觀課：低推論紀錄**。記時間、對象代碼、學生做了什麼、說了什麼（原話）、作品位置。不寫「很認真」「效果好」「混亂」等評價；評價留到議課的詮釋欄。
6. **議課：先事實、再詮釋**。依序：觀察到的事實 → 可能的詮釋（可以不只一種）→ 學生學習的證據 → 下一輪可以試的調整。授課教師先說自己的觀察與疑問。
7. **下一輪試作**：選一到兩個具體可試的調整，約定何時再看。
8. **隱私**：照片、錄影與紀錄的使用範圍、保存地點；只在社群研討中使用。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。

```bash
python3 "$SKILL_DIR/scripts/generate_open_lesson.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_open_lesson.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/open-lesson.docx"
```

語意閘門會擋下：各階段缺少對應內容（備課缺準備、觀課缺紀錄、議課缺討論）、觀察焦點超過 3 個、觀察紀錄或議課事實欄出現評價性用語。

## 品質關卡

- 觀察焦點與學習目標一致，且是看學生。
- 觀察紀錄任何人讀都能想像當時畫面。
- 議課的詮釋都能指回具體事實。
- 下一輪試作具體到可以排進下一節課。
- 紀錄沒有學生姓名或可辨識的照片。
