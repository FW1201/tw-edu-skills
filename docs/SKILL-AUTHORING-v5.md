# v5 技能撰寫規範

v5 的目標是讓每支技能內部有完整的思維路線，而不只是輸出格式。模型讀完 SKILL.md 就應該知道：什麼情況用這支、要先問什麼、怎麼一步一步判斷、哪些事不能做、做完交給誰。

## SKILL.md 結構

frontmatter：

```yaml
---
name: tw-edu-<名稱>
description: <一句定位>。<做什麼的具體描述>。適用於<使用者會說的觸發詞>。<必要時：不適用的情況改用哪支>
metadata:
  version: <x.y.z>
  author: 奇老師・數位敘事力社群
  category: <八個面向之一>
---
```

- description 40–220 字，必須含「適用於」與教師實際會說的詞。
- category 必須與 manifest 相同：課程設計、評量命題、教材資源、學生表現、班級經營、教育行政、教師專業、套組設定。

本文七個 `##` 章節，順序固定：

1. **定位與邊界**：做、不做、近似反例（使用者這樣說時應改用哪支技能）。
2. **開始前**：讀 `references/common/workflow.md` 與 `teacher-profile.md`；必要情境；缺漏怎麼處理；涉及學生時先看紅旗頁。
3. **思維路線**：編號步驟。每步寫「要判斷什麼 → 依據 → 分支」，涉及判斷時分四欄（規範要求／已知事實／推論／待確認）。
4. **台灣情境要點**：課綱、法規、校內常見做法；細節放在 `references/` 並標查核日期。
5. **產出**：schema 重點欄位、CLI（先 `--validate-only` 再 `--output`）、語意閘門會擋下什麼。
6. **品質關卡**：交付前逐項確認的清單。
7. **交接**：下一步該用哪支技能，以及要帶過去的資料。

`validate_skills.py` 會檢查上述章節、description 長度與「適用於」、category 一致。

## 細節放在 references

- SKILL.md 控制在約 150 行內，只放判斷流程與指引。
- 法規條次、表格、範例句型放在 `references/<主題>.md`，從 SKILL.md 以相對連結引用。
- 每份 references 開頭寫查核日期；法規主張同步記錄在根目錄 CITATIONS.md。

## 法規與事實

- 只寫查得到的條次；查不到就寫「待查」，不憑記憶寫時限或金額。
- 法規用轉述，不大段照抄；正式引用請使用者回查官方頁面。
- 涉及安全的紅旗（霸凌、性別事件、兒少保護、自傷傷人、校安、長期缺席）一律連到 `references/common/safety-red-flags.md`。

## 語意閘門

JSON Schema 管欄位格式，`shared/runtime/edu_runtime/semantics.py` 管 schema 表達不了的規則：

- **錯誤**（擋下，不產生檔案）：違反法規明文、資料不守恆、會造成傷害的內容（例如體罰措施、診斷標籤、學生姓名）。
- **提醒**（寫入 `.validation.json` 的 `advisories`）：慣例性建議、待確認項目、「生成不代表已核定或已發文」等聲明。
- 否定句不觸發禁用詞（「不得體罰」不會被當成體罰措施）。

每條錯誤規則都要有一個會被擋下的測試案例（`tests/test_v5_semantics.py`）。

## 新增技能的門檻

同時滿足才新增獨立技能，否則併入既有技能的模式：

- 有頻繁且清楚的獨立使用者請求。
- 主要輸入、工作責任與產出和既有技能不同。
- 至少兩個正例與一個近似反例能說明路由邊界（寫進 `docs/eval/v5-routing-cases.md`）。
- 可單獨安裝與運作，其他技能只是選用交接。
- 有可驗證的語意閘門或資料檢查，不只是產生一份漂亮文件。

## 隱私

- 學生一律用代碼；涉及學生的 schema 用代碼格式檢查擋下姓名。
- 設定檔只存一般教學偏好。
- 輸出若含個別學生資訊，品質關卡要提醒存放與傳遞方式。
