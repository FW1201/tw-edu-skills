# 專題式學習

專題的價值在於學生真的面對一個值得回答的問題，並在多次回饋與修正中做出給真實觀眾看的成果。本技能把這個過程拆成可管理的里程碑。

## 定位與邊界

- **做**：驅動問題設計與檢核、真實情境、里程碑與交付、鷹架與資源、學生選擇、回饋修正、公開成果、過程與成品評量。
- **不做**：單節教案（→ `tw-edu-lesson-plan-108`）、多科協同的課綱配置（→ `tw-edu-interdisciplinary`）、研究論文指導。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`。

必要情境：學段、總週數與每週節數、學生先備、可用資源（場域、設備、校外夥伴）。資源未確認時標待確認，不預設能校外教學。

## 思維路線

1. **驅動問題檢核**：
   - 開放：沒有單一標準答案。
   - 真實：連到學生生活、社區或真實需求。
   - 可探究：學生在可用時間內能蒐集資料並回答。
   - 有挑戰：需要學習新的知識或技能。
   不符合的問題先改寫，例如把「什麼是空汙」改成「我們學校周邊的空氣品質，什麼時候最需要注意？」。
2. **最終成果與觀眾**：成果給誰看（社區、家長、學弟妹、公部門）？觀眾決定成果的形式與品質標準。
3. **里程碑**：從成果倒推，每個里程碑有交付物、截止時間與回饋方式（同儕、教師、外部）。
4. **鷹架**：學生在哪一步最容易卡住？提供範例、資料清單、訪談範本、工作分配表。
5. **學生選擇**：子題、研究方法、成果形式至少一項由學生決定。
6. **回饋修正**：至少安排一次「看到回饋 → 修改」的循環，並保留修改前後版本。
7. **評量**：過程（分工、紀錄、修正）與成品都要評；用規準讓學生事先知道標準。
8. **安全與可行**：涉及實驗、戶外、訪談陌生人時，依學校規定確認安全條件與家長同意，通用草稿不宣稱已通過安全審核。

## 台灣情境要點

- 常見場域：彈性學習課程的專題探究、高中自主學習與探究實作、國中小議題探究課程。
- 涉及訪談或問卷時，提醒學生只蒐集必要資料、取得同意，未成年受訪者需家長同意。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。重點欄位：`driving_question`、`authentic_context`、`milestones`（交付物、期限、回饋）、`final_product`、`assessment_criteria`。

```bash
python3 "$SKILL_DIR/scripts/generate_pbl.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_pbl.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/pbl.docx"
```

## 品質關卡

- 驅動問題通過四項檢核。
- 每個里程碑都有交付物與回饋方式。
- 至少一次修改循環。
- 評量同時涵蓋過程與成品。
- 資源與安全條件標明已確認或待確認。
