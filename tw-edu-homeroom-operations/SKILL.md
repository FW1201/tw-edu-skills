# 導師日常與學期事務

把導師一學期要「讓班級運轉起來」的事務排成可執行的程序、分工與時間軸，並把屬於學校行政程序的部分交回權責單位。

## 定位與邊界

- **做**：開學第一週流程、座位與輪值、幹部與職務設計（任務、權限、輪替）、每日出缺勤確認與預警門檻、聯絡簿與群組規則、載具與手機約定、學期末交接包。
- **不做**：班級規範與關係經營（→ `tw-edu-classroom-culture`）、個別學生行為計畫（→ `tw-edu-behavior-support`）、事件處理與通報（→ `tw-edu-incident-response`）、給家長的個別訊息（→ `tw-edu-parent-communication`）。
- **近似反例**：「幫我想班規」屬班級文化，不是本技能；「學生連三天沒來怎麼辦」先讀紅旗頁，再用本技能補預警流程。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查工作區 `teacher-profile.md`（學段、班級人數、是否兼行政、學校規模）。本次要求優先於設定檔。

必要情境：學段與年級、時期（開學／學期中／學期末）、班級人數、學校已有的規定（手機、點名系統、群組平台）。未提供的標「未說明」；只有學校規定會改變做法時才追問。

若素材出現長期缺席、疑似受虐或其他紅旗，先讀 [紅旗與通報分流](references/common/safety-red-flags.md)。

## 思維路線

1. **先分權責**：這件事是「行政程序」還是「班級慣例」？
   - 行政程序（請假核准、缺席與中輟通報、獎懲、特教與輔導資料調閱）→ 只寫「交給哪個處室、何時、帶什麼資料」，不替學校決定。
   - 班級慣例（座位、輪值、幹部職務、聯絡簿格式）→ 導師與學生共同決定，寫成可執行程序。
2. **找出每天必須發生的事**：到校確認、午餐整潔、聯絡簿、放學。每項寫「誰、何時、步驟、怎麼檢核」。沒有檢核方式的程序會在第三週失效。
3. **設計職務而不是頭銜**：每個幹部或職務都要有具體任務、可以做與不能做的事（例如提醒與紀錄，但不處罰同學）、輪替週期、教師如何支持。避免職務總落在同幾位學生身上，或成為標籤。
4. **出缺勤預警**：每日確認 → 當日未到且未請假的聯繫時點 → 連續缺席的關懷 → 法定通報門檻（國中小：未經請假或原因不明連續達 3 日）。門檻與通報對象寫清楚並附依據，實際通報由學校權責單位執行。
5. **溝通管道分流**：聯絡簿與班級群組只放全班性資訊；個別學生事項改私訊、電話或面談。寫出每個管道的隱私規則。
6. **載具與手機**：先查學校規定，班級約定只能在學校規定範圍內細化；違反時的回應採「提醒 → 個別討論 → 通知家長」，不沒收超出學校規定的時間、不公開處理。
7. **排時間軸**：開學前一週／第一週／第三週檢視／期中／期末。第三週安排一次「程序是否有效」的檢視。
8. **學期末交接**：只交接下一位導師需要的資訊（班級優勢、持續中的支持、紀錄放在哪裡）；輔導、特教與獎懲資料依原單位規定轉銜，不放進一般交接包。

## 台灣情境要點

- 長期缺席通報門檻與程序、手機與載具、交接資料範圍：見 [導師事務情境要點](references/homeroom-context.md)。
- 個資：班級群組與聯絡簿不揭露個別學生的成績比較、行為紀錄、家庭狀況或特教身分。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。重點欄位：`boundaries`（行政程序／班級決定）、`routines`（含 `check`）、`roles`（任務、權限、輪替）、`attendance`（門檻、通報對象、依據）、`timeline`、`handover`。

```bash
# SKILL_DIR 為本技能安裝目錄；TASK_DIR 為目前工作區的任務輸出目錄。
python3 "$SKILL_DIR/scripts/generate_homeroom.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_homeroom.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/homeroom.docx"
```

依賴：`python3 -m pip install -r "$SKILL_DIR/requirements.txt"`。學期末交接（`period` 為學期末交接）必須附 `handover`，否則驗證失敗。

## 品質關卡

- 每個例行程序都有負責人與檢核方式。
- 每個職務都有權限邊界，沒有「由學生處罰學生」的設計。
- 出缺勤門檻與通報對象有依據，且標示由學校權責單位執行。
- 溝通管道各有隱私規則；個別學生事項不進群組。
- 交接包不含輔導紀錄、特教鑑定資料或家庭細節。
- 學校規定未知的項目列在 `pending`，不補造。

## 交接

- 班級規範、儀式、修復路徑 → `tw-edu-classroom-culture`。
- 需給家長的通知或個別溝通 → `tw-edu-parent-communication`（帶 `communication` 規則）。
- 個別學生持續困難 → `tw-edu-student-guidance-advice` 或 `tw-edu-behavior-support`。
- 班親會議程與紀錄 → `tw-edu-meeting-facilitator`。
