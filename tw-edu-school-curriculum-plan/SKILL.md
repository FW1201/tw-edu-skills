# 學校課程計畫

協助教務處、課程召集人或課程小組把學校的願景一路對應到每個年級的課程與單元，並把節數、目標與審議流程整理成可送課發會的草稿。

## 定位與邊界

- **做**：願景 → 學生圖像 → 課程目標 → 課程架構 → 單元規劃的對應、節數加總檢查、議題融入、審議與備查流程、縣市格式提醒。
- **不做**：單一課堂教案（→ `tw-edu-lesson-plan-108`）、一個學期的教學進度（→ `tw-edu-curriculum-mapper`）、替學校決定節數配置或願景。
- **近似反例**：「我這學期國文要上哪些課」是課程地圖，不是學校課程計畫。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`（學校類型、縣市、職務）。

必要資訊：學校類型、計畫類型（校訂、彈性學習、總體）、學校願景與學生圖像、各年級**由學校提供**的節數配置、縣市備查格式（若有）。節數必須由使用者或學校文件提供；技能不臆測各年級應有的節數，未提供就只檢查目標對應，不檢查加總。

## 思維路線

1. **由上而下對應**：願景 → 學生圖像（3–5 項）→ 課程目標。每個目標至少連到一個學生圖像；沒有對應的圖像要標出來，代表課程沒有照顧到。
2. **課程架構**：每個年級的每門課寫類別、週節數、週數、對應目標。國中小彈性學習課程常見類別為統整性主題／專題／議題探究、社團活動與技藝、特殊需求領域、其他類；高中為校訂必修、多元選修、團體活動、彈性學習時間。類別名稱依學校採用的課綱與縣市格式調整。
3. **檢查覆蓋**：每個課程目標都至少有一門課負責；沒有被任何課承擔的目標要提出來。
4. **檢查節數**：若提供了各年級規定節數，逐年級加總比對；不符時列出差額，由學校決定調整哪門課。
5. **單元規劃**：每門課列單元、週次、學習重點、評量方式、融入議題；單元要能看出課程目標如何被達成。
6. **縱向連貫**：不同年級的同一系列課程是否由淺入深，避免重複或斷層。
7. **審議與備查**：領域教學研究會或課程小組提案 → 課程發展委員會審議 → 依主管機關規定期程報備查。寫出時程與負責處室。
8. **格式**：各縣市的課程計畫表格與期程不同，最後依當年度教育局處通知調整欄位。

## 台灣情境要點

- 課程架構類別、審議流程的參考與注意事項見 [課程計畫要點](references/curriculum-plan-context.md)。
- 課綱查詢（學習重點代碼）：

```bash
python3 "$SKILL_DIR/scripts/lookup_curriculum.py" --domain 綜合活動 --keyword 探索 --limit 10
```

查詢說明見 [課綱指標查詢](references/108_subject_indicators.md)。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。

```bash
python3 "$SKILL_DIR/scripts/generate_curriculum_plan.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_curriculum_plan.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/curriculum-plan.docx"
```

語意閘門會擋下：目標編號重複、課程對應到不存在的目標、有目標沒有任何課程承擔、單元所屬課程不在架構表、提供規定節數時加總不符。

## 品質關卡

- 每個學生圖像至少被一個目標對應，每個目標至少被一門課承擔。
- 節數來源有寫（課發會決議、教育局通知等）。
- 單元的評量方式能看出學生達成目標的證據。
- 審議流程有時程與負責處室。
- 縣市格式差異列為待確認。

## 交接

- 單元發展成教案 → `tw-edu-lesson-plan-108`。
- 學期進度表 → `tw-edu-curriculum-mapper`。
- 課發會議程與紀錄 → `tw-edu-meeting-facilitator`。
- 報主管機關的公文 → `tw-edu-official-document`。
