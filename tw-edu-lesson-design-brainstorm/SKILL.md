# 課程設計發想引導

這是一個**對話式**技能：不是一次生成完整教案，而是陪老師一步一步把模糊的想法變成可以設計的構想。老師做決定，技能提供選項、追問與檢核。

## 定位與邊界

- **做**：分輪引導發散與收斂、提供切入角度選項、以逆向設計對齊學習重點與評量證據、活動雛形、構想書 docx、指出下一步該用哪個技能。
- **不做**：完整教案與時間配置（→ `tw-edu-lesson-plan-108`）、完整 PBL 流程（→ `tw-edu-pbl-designer`）、跨科協同細節（→ `tw-edu-interdisciplinary`）。
- **近似反例**：老師已有明確目標與活動，只要排成教案 → 直接用 lesson-plan-108。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`（科目、學段、教材版本、常用節數）。已知的不要再問。

起點只需要：一個議題或課題。學段、科目、節數若未知，第一輪一起問。

### 對話節奏

- **每輪最多 2–3 個問題**，每題附 3–4 個可選答案加「其他」，讓老師用選的就能前進。
- 每輪結束先用一兩句摘要目前的決定，再問下一輪。
- 老師說「你幫我選」時，提出建議與理由，但仍讓老師確認。
- 老師隨時可以跳回上一輪改決定。

## 思維路線

1. **第一輪：定錨**。學段、科目、可用節數與資源。順便問：這個議題對學生來說，最可能連到哪個生活經驗？
2. **第二輪：發散**。用五個方向各給 2–3 個點子，請老師勾選有感覺的：
   - 學生經驗連結（他們每天碰到什麼）
   - 真實情境（校內、社區、新聞、資料）
   - 跨領域角度（哪些科目的概念能幫忙理解）
   - 議題融入（108 課綱 19 項議題中相關者）
   - 核心問題（開放、值得討論、沒有單一答案）
3. **第三輪：收斂**。從勾選中選一個切入點，寫下選擇理由與暫不採用的點子。檢核三件事：學生做得到嗎？資料取得得到嗎？節數放得下嗎？
4. **第四輪：大概念與學習重點**。用一句話寫出學生學完應該帶走的大概念；對應學習表現與學習內容代碼，用課綱查詢器回查，查不到標待確認。
5. **第五輪：評量證據**（逆向設計）。學生要完成什麼表現任務，才能證明理解了？寫出成功準則。
6. **第六輪：活動雛形**。引起動機、發展、綜合、延伸各一個構想，粗估分鐘數；活動要能產生第五輪的證據。
7. **收尾**：列出還沒決定的事，建議下一個技能（教案、PBL、跨領域或差異化），並產生構想書。

## 台灣情境要點

- 108 課綱素養導向的四個設計重點、19 項議題清單、逆向設計提問，見 [發想參考](references/brainstorm-guide.md)。
- 課綱代碼查詢：

```bash
python3 "$SKILL_DIR/scripts/lookup_curriculum.py" --domain 社會 --keyword 環境 --limit 10
python3 "$SKILL_DIR/scripts/lookup_curriculum.py" --domain 國語文 --code 5-IV-2
```

查詢說明見 [課綱指標查詢](references/108_subject_indicators.md)。

## 產出

對話完成後依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。

```bash
python3 "$SKILL_DIR/scripts/generate_design_brainstorm.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_design_brainstorm.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/design-brief.docx"
```

語意閘門：未查核的課綱代碼必須附查核說明；選定的切入點若不在發散清單中，驗證紀錄會提醒。

## 品質關卡

- 發散的五個方向都有內容，不是只列一種角度。
- 切入點有理由，也記下放棄了什麼。
- 大概念是一句可遷移的理解，不是課本標題。
- 評量證據先於活動設計，且活動能產生該證據。
- 課綱代碼有查核狀態。

## 交接

- 寫成完整教案 → `tw-edu-lesson-plan-108`（帶大概念、學習重點、評量證據、活動雛形）。
- 發展成專題 → `tw-edu-pbl-designer`（帶核心問題與真實情境）。
- 多科協同 → `tw-edu-interdisciplinary`（帶跨領域角度）。
- 需要分層 → `tw-edu-differentiated`。
