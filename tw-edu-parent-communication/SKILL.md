# 親師溝通

親師溝通的目標是讓家長成為合作夥伴。先選對管道，再用事實開頭，最後給家長一件具體可以做的事。

## 定位與邊界

- **做**：管道與敏感度判斷、事實與關切分開、訊息草稿、合作請求、會談與班親會安排、群組規範、敏感對話腳本。
- **不做**：學校機關名義的正式公告（→ `tw-edu-official-document`）、事件通報（→ `tw-edu-incident-response`）、代為發送訊息。

## 開始前

讀取 [共用工作方式](references/common/workflow.md)，檢查 `teacher-profile.md`（學段、聯絡方式、語氣偏好）。

必要情境：對象（全班、個別、家長代表）、溝通目的、已知事實、希望家長配合的事、時間點。稱謂、日期、聯絡方式都要核對；學校的承諾或決定沒有依據時不寫入。

**發送需要老師本人執行**：本技能只產生草稿，`send_status` 預設為草稿。

## 思維路線

1. **判斷敏感度**：
   - 一般：全班性活動、作業、提醒。
   - 個別：某位學生的學習或行為。
   - 敏感：衝突、健康、家庭、情緒。
   - 正式程序：已進入學校調查、通報或申訴程序的事。
2. **依敏感度選管道**：一般 → 公告、聯絡簿、群組；個別 → 私訊、電話、聯絡簿個別留言；敏感 → 電話或面談；正式程序 → 透過學校行政協調、書面通知或面談。個別與敏感事項不在群組或公告中處理。
3. **事實先行**：先寫觀察到的事實（時間、行為、次數），再寫老師的關切（標明是老師的觀察與想法），不寫推測的家庭原因。
4. **合作請求**：給家長一件具體、做得到的事，以及回覆的方式與時間。
5. **敏感對話**：開場表達共同目標（都希望孩子好）→ 說事實 → 聽家長的觀察 → 一起決定下一步 → 約定追蹤。面對情緒先回應感受，不爭論對錯；需要時邀請行政或輔導老師一起。
6. **班親會**：議程、時間配置、分工；班級經營理念、學習重點、聯絡方式、家長可以參與的方式。不在會中討論個別學生。
7. **群組規範**：用途、回覆時間、個別事項改私訊、不轉傳截圖、不討論其他孩子。
8. **回報狀態**：草稿、待主管確認、已發送、家長已讀或已回覆要分開記錄。

## 台灣情境要點

- 評量結果每學期至少書面通知一次，不得公開個別學生排名（國中小學習評量辦法第11條）。
- 涉及霸凌、性平、兒少保護等正式程序時，說明程序與聯絡窗口，不透露另一方學生資料，也不預告結果。

## 產出

依 [輸入規格](schemas/input.schema.json) 建立 JSON，[範例](examples/example.json) 只看結構。v5 必填 `audience`、`channel`、`sensitivity`、`facts`、`send_status`。

```bash
python3 "$SKILL_DIR/scripts/generate_parent_comm.py" --input "$TASK_DIR/input.json" --validate-only
python3 "$SKILL_DIR/scripts/generate_parent_comm.py" --input "$TASK_DIR/input.json" --output "$TASK_DIR/parent-message.docx"
```

語意閘門會擋下：非一般事項寄給全班家長、非一般事項使用公告、正式程序事項未經行政協調、書面通知或面談。

## 品質關卡

- 管道與敏感度相符。
- 第一段是事實，不是評價。
- 有具體的合作請求與回覆方式。
- 沒有其他學生的資訊。
- 標示為草稿，未宣稱已發送。

## 交接

- 正式公告或學校名義通知 → `tw-edu-official-document`。
- 班親會議程與紀錄 → `tw-edu-meeting-facilitator`。
- 行為支持合作 → `tw-edu-behavior-support`。
